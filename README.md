# b2b-order-bridge

Демонстрация backend-интеграций B2B-заказов с небольшим интерфейсом оператора на Blazor.

## Запуск

Нужен Docker Desktop с Linux-контейнерами. Из корня репозитория:

```powershell
docker compose -f B2BOrderBridge/docker-compose.yml up -d --build
```

- Интерфейс: http://localhost:8090
- Swagger API: http://localhost:8088/swagger
- PostgreSQL: localhost:5432

Порты можно переопределить переменными `WEB_PORT`, `API_PORT`, `POSTGRES_PORT`.
Compose запускает Web, API и PostgreSQL, API применяет миграции в Development.
Данные сохраняются в Docker volume. Автоматического заполнения заказами нет.

## Сценарий демонстрации

1. Откройте интерфейс и нажмите «Создать заказ».
2. Заполните источник, внешний номер, компанию, ИНН, email и позиции.
3. После сохранения откроется карточка заказа с запланированными интеграциями.
4. Нажмите «Обновить» после фоновой обработки: worker опрашивает очередь каждые 10 секунд.
5. Раскройте «История попыток» для просмотра результата, HTTP-статуса, ошибки и Trace ID.
6. Вернитесь к списку: доступны поиск, сортировка и пагинация.

Набор интеграций определяет backend-планировщик. Текущий Telegram-адаптер — mock;
успешный статус в демо не означает отправку сообщения в настоящий Telegram.
Mock Telegram случайным образом возвращает успех, временный сбой или отказ.
Обработчики Битрикс24 и 1С пока не зарегистрированы: их интеграции остаются в ожидании.
Диадок ожидает выполнения предварительных условий.
Повторное создание с той же парой источник / внешний номер обрабатывается backend;
форма показывает ошибки проверки и конфликтов API.

## Frontend

`OrderBridge.Web` — отдельный Blazor Web App (.NET 10, Interactive Server).
Компоненты обращаются к типизированному `OrderBridgeApiClient`, который вызывает REST API
с сервера. Проект не ссылается на Domain, Application или Infrastructure;
модели HTTP-контрактов находятся в `Web/Models`. CORS для этого способа взаимодействия не требуется.

В интерфейсе есть список заказов, форма с добавлением/удалением позиций,
карточка заказа и история попыток с отдельной пагинацией. Все данные поступают из API.
Предусмотрены состояния загрузки, пустых результатов, ошибок и потери соединения.
Обновление статусов выполняется вручную. Время отображается в UTC.
Web не добавляет авторизацию; текущий вариант предназначен для локальной демонстрации.

Для разработки frontend локально при запущенных API и PostgreSQL:

```powershell
cd B2BOrderBridge
dotnet run --project OrderBridge/OrderBridge.Web
```

Адрес API задаётся через `OrderBridgeApi:BaseUrl` в `appsettings.json`
или переменную окружения `OrderBridgeApi__BaseUrl` (по умолчанию `http://localhost:8088/`,
в Docker — `http://api:8080/`). Браузеру нужен доступ только к Web, включая WebSocket для Blazor.

## Проверка frontend

```powershell
dotnet test B2BOrderBridge/tests/OrderBridge.Web.Tests
```

Тесты проверяют HTTP-контракты, экранирование поиска, передачу ошибок валидации,
фильтрацию истории, валидацию позиций и округление суммы.
